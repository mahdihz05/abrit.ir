## محدودیت‌های ساختاری موجود (تعیین‌کننده تصمیم‌ها)

- hero.points حداکثر ۵ آیتم متنی: Part 2 هیرو (۵ تمایز) دقیقاً جا می‌شود.
- featureGrid.items حداکثر ۱۲ آیتم با title و description اجباری: ۱۳ فناوری خانه گروه‌بندی شد؛ آیتم‌های تک‌عبارتی توضیح مشتق از واژگان متن گرفتند (نیازمند تأیید).
- cta فقط یک دکمه دارد و hero دو دکمه: CTA پایانی بکاپ (دو دکمه) با بلوک hero ساده پیاده شد.
- هدر فقط ۲ سطح تخت رندر می‌کند: تب خدمات با ۳ گروه قابل نمایش نیست؛ منوی عمومی فقط مقصدهای واقعی را نشان می‌دهد.
- فوتر فقط لینک‌های تخت سطح اول را رندر می‌کند: ساختار ۳ ستونه در دیتا ذخیره شد برای ارتقای بعدی کامپوننت.
- لینک پورتال مشتریان در فوتر رندر نمی‌شود: شکاف ثبت‌شده برای فاز بعد (خارج از اسکوپ).

## تصمیم‌های منو

1. هدر عمومی فقط مقصد واقعی دارد: خانه / خدمات (بکاپ و بازیابی) / تماس با ما. لینک مرده ممنوع.
2. ساختار کامل منوی درخواستی به‌صورت disabled در سید ذخیره شد تا با ساخته‌شدن صفحات فقط فعال شوند.
3. آیتم «محصولات مستقل» چون متن باز است سید نشد؛ پس از نهایی‌شدن متن اضافه می‌شود.
4. جابه‌جایی زمان‌دار هیرو، میندمپ، اینفوگرافیک و رادارچارت نیاز به کامپوننت جدید دارند (خلاف قید عدم تغییر ساختار) و در بک‌لاگ فاز بعد ثبت شدند.
