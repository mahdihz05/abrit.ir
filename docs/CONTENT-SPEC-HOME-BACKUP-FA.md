## ۳. صفحه Abrit Backup

### Section 1 — هیرو
- تیتر: «اطلاعات سازمان شما، همیشه یک مسیر مطمئن برای بازگشت دارد»
- لید: «Abrit Backup پشتیبان‌گیری، پایش و بازیابی اطلاعات و سرویس‌های حیاتی سازمان را در قالب یک فرآیند مدیریت‌شده اجرا می‌کند؛ تا سازمان شما با اطمینان بیشتری به فعالیت خود ادامه دهد»
- استریپ ۴ آیتمی (با انیمیشن مناسب):
  1. پشتیبان‌گیری از سرویس‌های سازمانی
  2. مدیریت فایل‌ها و داده‌های حیاتی
  3. بررسی سلامت نسخه‌های پشتیبان
  4. بازیابی اطلاعات در زمان نیاز

### Section 2 — معرفی («Abrit Backup چیست؟»)
- تیتر: «Abrit Backup چیست؟»
- زیرتیتر: «یک سرویس مدیریت‌شده برای پشتیبان‌گیری و بازیابی اطلاعات سازمان»
- متن: «Abrit Backup مجموعه‌ای از فرآیندها و فناوری‌های پشتیبان‌گیری است که از طراحی سیاست Backup و مدیریت نسخه‌ها تا پایش سلامت و بازیابی اطلاعات و سرویس‌های سازمان را پوشش می‌دهد.»

### Section 3 — دو پارت
**Part 1 — «چرا Backup فقط ذخیره یک کپی از اطلاعات نیست؟»**
1. «اطلاعات ارزشمند، نیازمند برنامه مشخص هستند» — «داده‌های سازمان بخشی از سرمایه کسب‌وکار هستند و برای حفاظت از آن‌ها به یک فرآیند مشخص نیاز دارند.»
2. «Backup زمانی ارزش واقعی ایجاد می‌کند که مدیریت شود» — «پایش سلامت نسخه‌ها، زمان‌بندی مناسب و اطمینان از قابلیت بازیابی، Backup را به یک فرآیند قابل اتکا برای سازمان تبدیل می‌کند.»
3. «سرویس‌های حیاتی به آمادگی بیشتری نیاز دارند» — «سرورها، فایل‌ها و نرم‌افزارهای سازمانی باید در شرایط مختلف امکان بازگشت سریع داشته باشند.»

**Part 2 — «Abrit Backup چه چیزهایی را محافظت می‌کند؟»**
- لید: «پشتیبان‌گیری برای بخش‌های حیاتی سازمان»
- VM Backup (محافظت از ماشین‌های مجازی و سرویس‌های سازمانی): Application Server · Database Server · File Server · ERP Server
- File Backup (حفاظت از فایل‌ها و اطلاعات کاری): اسناد سازمانی · فایل‌های کاربران · پوشه‌های اشتراکی · داده‌های Workspace
- Application Backup (حفظ سرویس‌های مهم سازمان): ERP · Database · Configuration سرویس‌ها

### Section 4 — «چرا Abrit Backup؟»
- لید: «Backup یک نرم‌افزار نیست؛ یک مسئولیت عملیاتی است»
- ۳ کارت:
  1. طراحی متناسب با سازمان — «سیاست Backup بر اساس سرویس‌ها، داده‌ها و نیازهای کسب‌وکار طراحی می‌شود.»
  2. مدیریت و پایش مستمر — «وضعیت نسخه‌های پشتیبان به‌صورت مستمر بررسی و کنترل می‌شود.»
  3. اطمینان از قابلیت بازیابی — «در Abrit Backup، موفق بودن فرآیند پشتیبان‌گیری پایان کار نیست؛ هر Backup باید بررسی شود و قابلیت بازیابی آن مشخص باشد»

### Section 5 — فرایند ۴ مرحله‌ای («از طراحی تا بازیابی؛ Backup تحت مدیریت Abrit»)
1. طراحی سیاست Backup — «تعیین روش، زمان‌بندی و سطح پشتیبان‌گیری بر اساس نیاز سازمان.»
2. اجرای Backup — «پیاده‌سازی فرآیندهای منظم برای سرویس‌ها و داده‌های موردنظر.»
3. بررسی و پایش — «کنترل وضعیت نسخه‌های پشتیبان و عملکرد فرآیندها.»
4. بازیابی — «Restore اطلاعات و سرویس‌ها بر اساس برنامه بازیابی سازمان.»

### Section 6 — فناوری و معماری («فناوری و معماری Abrit»)
- لید: «زیرساخت Abrit Backup از فناوری‌های تخصصی پشتیبان‌گیری، Monitoring و ابزارهای بازیابی تشکیل شده است تا وضعیت Backupها قابل پایش، ارزیابی و مدیریت باشد.»
- نکته طراحی: نمایش کنار هم یا اسلاید با انیمیشن.
- ۳ گروه:
  - زیرساخت Backup (مدیریت Backup ماشین‌های مجازی و سرویس‌های سازمانی): Proxmox Backup Server · VM Backup · Scheduled Backup
  - مدیریت و کنترل Backup (اطمینان از سلامت فرآیند): Monitoring · Verification · Restore Test · Report
  - Business Continuity (طراحی بازیابی سازمان): RPO · RTO · Recovery Planning · Disaster Recovery

### Section 7 — ویترین صفحه (خیلی مهم، تو چشم)
- تیتر: «Backup هوشمند، بر اساس اولویت‌های واقعی سازمان»
- متن: «در Abrit Backup، سیاست پشتیبان‌گیری و بازیابی بر اساس اولویت‌ها، حساسیت داده‌ها و الزامات عملیاتی هر سازمان طراحی می‌شود. معیارهای RPO و RTO کمک می‌کنند سطح حفاظت و زمان بازیابی هر سرویس به‌صورت شفاف و متناسب با نیاز کسب‌وکار و الزامات مورد انتظار سازمان مشخص شود.»
- کارت اول | RPO سطح حفاظت از داده‌ها: «RPO مشخص می‌کند سازمان به چه فاصله زمانی از نسخه‌های اطلاعات نیاز دارد؛ بر همین اساس، زمان‌بندی Backup برای هر سرویس مطابق سطح حفاظت مورد انتظار مشتری طراحی می‌شود.»
- کارت دوم | RTO زمان هدف برای بازگشت سرویس: «RTO مشخص می‌کند هر سرویس در چه بازه زمانی باید دوباره در دسترس قرار گیرد؛ بنابراین فرآیند Recovery متناسب با اولویت عملیاتی سازمان برنامه‌ریزی می‌شود.»

### Section 8 — مسیر شروع همکاری + CTA پایانی
- مراحل: Assessment (بررسی سرویس‌ها، داده‌ها و نیاز سازمان) ← Design (طراحی سیاست Backup، Retention و Recovery) ← Deployment (راه‌اندازی Backup و تنظیم فرآیندها) ← Managed Backup (Monitoring، تست Restore و نگهداری مستمر)
- CTA: «برای اطلاعات حیاتی سازمان، Backup را به یک فرآیند قابل اتکا تبدیل کنید» + «Abrit Backup پشتیبان‌گیری، پایش و بازیابی داده‌ها و سرویس‌های سازمان را بر اساس نیاز واقعی کسب‌وکار شما مدیریت می‌کند.»
- دکمه‌ها: «طراحی راهکار Backup سازمانی» · «دریافت مشاوره تخصصی»

## ۴. جمع‌بندی تحلیلی (برای پیاده‌سازی)

- پیام کلیدی کل سایت: «مدیریت یکپارچه و پیشگیرانه IT به‌جای پشتیبانی موردی» — واژگان تکراری عمدی: یکپارچه، پیشگیری، فرایند، مستندسازی، اتوماسیون، پایش مستمر.
- ساختار روایی صفحه اول: هیرو (قول) ← تثبیت اعتماد (Section 2 ثابت) ← مزایا ← خدمات (۱۰) ← راهکارها (۶، میندمپ) ← فرایند (۴، اینفوگرافیک) ← فناوری (رادارچارت) ← فوتر + CTA ارزیابی.
- نیازهای بصری اعلام‌شده: S1 اسلایدر زمان‌دار / S2 ثابت / S3 تیتر وسط + گرید ۵تایی / S5 میندمپ متحرک / S6 اینفوگرافیک مرحله‌ای / S7 رادارچارت ۱۳ فناوری.
- صفحه Backup آینه همان روایت است در مقیاس یک سرویس: قول ← تعریف ← چرایی ← تمایز ← فرایند ← فناوری ← ویترین RPO/RTO (مهم‌ترین بخش صفحه) ← مسیر همکاری + دو CTA.
- ناوبری دو تب اصلی (خدمات، راهکارها) + سه گروه زیر خدمات (مدیریت‌شده / پکیج‌ها / مستقل)؛ آیتم «محصولات مستقل» متن باز و قابل بازنویسی است.
- ناهماهنگی کوچک برای تعیین‌تکلیف بعدی: Section 4 خانه «ERP و اتوماسیون» (Odoo) در برابر آیتم‌های منو (ERP، Automation جدا) و Section 7 خانه که ۱۳ فناوری را یکجا فهرست می‌کند — در رادارچارت باید به محورهای معنادار (امنیت، ذخیره‌سازی، پایش، اتوماسیون…) گروه‌بندی شود نه ۱۳ محور جدا.
